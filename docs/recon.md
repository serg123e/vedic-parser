# Разведка vedic-horo.com / vedic-horo.ru

Тестовый запрос:

```
https://vedic-horo.com/analyse.php?name=Ss&date=07.08.1983&time=23:00:00&latitude=55.45&longitude=37.37&timezone=+4
```

Дата проверки: 2026-09-12.

## 1. Доступ

| URL | Плоский `curl` | Комментарий |
|---|---|---|
| `https://vedic-horo.com/` | 200 | токен `token_security` берётся отсюда |
| `https://vedic-horo.com/analyse.php?...` | **403** | Cloudflare managed challenge (`cf-mitigated: challenge`, «Just a moment…») |
| `https://vedic-horo.com/horoscope.php?...` | 200 | упрощённая версия («я не астролог») |
| `https://vedic-horo.com/actions.php` | 200 | AJAX-API, **не** под челленджем |
| `https://vedic-horo.ru/analyse.php?...` | 200 | тот же движок, русские подписи |
| `https://vedic-horo.ru/actions.php` | 200 | то же API |

Выводы:

* Под Cloudflare спрятана **только страница `analyse.php` на домене `.com`**. Ни `.ru`,
  ни `horoscope.php`, ни `actions.php` челленджа не требуют. User-Agent, Referer и
  cookie на прохождение не влияют — правило срабатывает именно на этот путь.
* Челлендж не решается автоматически из этого окружения: скрипт Cloudflare
  обращается к `brunhild.challenges.cloudflare.com`, который блокируется egress-политикой
  (`ERR_TUNNEL_CONNECTION_FAILED`), поэтому `cf_clearance` не выдаётся.
* Рабочий путь без обхода защиты: **брать токен с главной `.com` и дёргать `actions.php`** —
  данные приходят на английском. Либо парсить `.ru/analyse.php` целиком (русский язык).

Примечание по окружению (не по сайту): Chromium через прокси отваливается с
`ERR_CONNECTION_RESET`, пока не отключён post-quantum ClientHello. Рабочие флаги:
`--disable-features=EncryptedClientHello,UseMLKEM,PostQuantumKyber --ssl-version-max=tls1.2`.

## 2. Формат ответа

JSON нигде нет — всё отдаётся **готовым HTML**. В inline-скриптах страницы данных
о карте тоже нет (только аналитика и CSRF-токен). То есть парсер — это парсер HTML.

Полезно для парсинга:

* `.desc`-ссылки несут машинные ключи: `planet?Su`, `in-sign?Su-Cn`, `in-house?Su-4`,
  `nakshatra?Asl`, `lord-in?5-4`.
* Классы планет: `Su Mo Ma Me Ju Ve Sa Ra Ke As`.
* Строки даш несут атрибуты `start` / `end` в формате `dd.mm.yyyy HH:MM` — даты
  лучше брать из них, а не из текста (текст локализован: «23 ноя 1978»).
* `title`-атрибуты содержат расшифровки сокращений («ФБ» → «Функциональная
  благотворность», «НДБ» → «Нулевая Диг-бала…», отношение знака → «Друг»).

## 3. Что отдаёт `analyse.php` (страница целиком ≈ 217 КБ)

```
#natal-data            имя, дата/время, TZ, координаты (шапка)
#menu-analysis         вкладки: Основная | Совместимость | Варшапхала | Мухурта | Транзиты
                       (все, кроме «Основной», платные)
#tab-natal
  #chart-natal         3 × div.chart-block — по умолчанию D1, D9 и карта от Луны
  #natal-info          главная таблица планет + Аштакаварга
  #other / #upagrahas  вкладка «Разное»
  #periods             3 × div.dasha-block — вкладка «Периоды»
```

### 3.1 Карта (`div.chart-block`)

`div.chart-north` (или `.chart-south`) → SVG-сетка + 12 × `div.house`:

* `.sign > a.desc` — номер знака,
* `.planets > span.planet.<Xx>` — `Ma 02°`, `Ve R 15°` (`R` = ретро),
* `.aspects > u` — аспектирующие планеты,
* `.effects` — ссылки «Все аспекты / Аспекты / Аргала / 1-й дом»,
* `div.chart-data` — `.chart-name .chart-date .chart-time .chart-timezone .chart-latitude .chart-longitude`,
* `select.divisional` — 26 вариантов: `SL JC UG Mo Su AL D1 D2 D3 D4 D5 D6 D7 D8 D9 D10 D11 D12 D16 D20 D24 D27 D30 D40 D45 D60`.

### 3.2 Главная таблица планет (`#natal-info table.chart-info`)

11 строк (Асцендент + 9 грах + Кету), 15 колонок:

`планета | Карака | Градусы | Раши | Навамша | Накшатра (Пада, Упр) | Отношение | Дом | Управитель | ФБ | ЕБ | Шад-бала | Бинду (САВ/БАВ) | Положение | Планетная война`

Пример строки: `Солнце | АК | 21°05'41'' | Рак | Козерог | Ашлеша (2, Me) | Нейтрально | 4 | 5-го | Б | В | 124% | 26 / 7 | НДБ | -`

Ниже — 9 блоков `div.ashtaka-north`: `SAV` (сумма по 12 знакам) и по одному БАВ на
`As Su Mo Ma Me Ju Ve Sa`.

### 3.3 Вкладка «Разное»

* Особые лагны и спхуты: Бхава/Хора/Гхатика/Шри/Инду/Варнада/Пака/Каракамша Лагна,
  Пранапада, Кунда, Бхригу Бинду, Биджа/Кшетра/Йоги/Авайоги Спхута — градус, знак, накшатра (пада, упр).
* Панчанга: Восход, Закат, Хора, Вара, Титхи, Карана, Йога.
* Упаграхи (11): Дхума, Вьятипата, Паривеша, Индрачапа, Упакету, Гулика, Манди, Кала,
  Мритью, Ардхапрахара, Ямагантака — градус, знак, накшатра, дом.
* Айянамша, Сахайоги, Бадхака, Дагдха Раши, 22-я Дреккана, 64-я Навамша, Сарпа Дреккана, Виша Навамша.
* Чакры: 6 строк (Муладхара…Аджна) — элемент, знаки, планеты, что в знаке.

### 3.4 Вкладка «Периоды»

3 блока `div.dasha-block`, по умолчанию Вимшоттари, Чара (К.Н. Рао) и Нарайана.
Строка: `<tr start="07.08.1983 23:00" end="07.11.1983 06:32">` → период, дата, время, возраст.
Всего доступно 6 систем: `vimshottari yogini ashtottari chara_rao narayana navamsa`,
уровни вложенности 1–4, любая варга D1…D60.

## 4. API `actions.php` — основной интерфейс

```
POST /actions.php
Cookie: PHPSESSID=<с любой страницы того же домена>
action=<действие>&data=<карта>&token_security=<токен с той же страницы>&<параметры>
```

* `data` — pipe-строка: `name=Ss|date=07.08.1983|time=23:00:00|timezone=+4|latitude=55.45|longitude=37.37`
* `token_security` — hex-строка из inline-скрипта любой страницы домена
  (`var token_security = "…"`), валиден в паре со своим `PHPSESSID`.
* Требования проверены: без токена → 403, без cookie → 500, GET → 403,
  User-Agent значения не имеет. Ответ — HTML-фрагмент.

Проверенные действия (анонимно, без регистрации):

| action | параметры | что возвращает |
|---|---|---|
| `show-info` | `divisional`, `from` (`''`/`1` Солнце/`2` Луна/`AL`) | таблица планет + аштакаварга, ~26 КБ |
| `show-chart` | `divisional`, `style=North\|South`, `type` | одна карта (SVG + дома) |
| `show-chart-big`, `show-chart-overlay`, `show-chart-bhava` | то же | увеличенная / наложение / Бхава-Чалита |
| `show-other` | `divisional` | лагны, панчанга, упаграхи, чакры |
| `show-bhava` | `divisional` | таблица бхав: куспид, начало, конец, размер, планеты |
| `show-periods` | `divisional` | селекторы даш (6 систем × D1…D60 × уровни 1–4) |
| `show-dasha` | `dasha`, `level`, `divisional`, `cycle`, `current` (`d.m.yyyy H:M`), `search` | таблица периодов (level=3 → ~190 КБ) |
| `show-current-periods` | — | текущий период (`ВД: Ve - Mo - Ra`) |
| `show-bala` / `show-shad-bala` | `divisional` | Шад-бала: Стхана/Диг/Кала/Чешта/Дрик/Наисаргика/Юддха/Ишта/Кашта |
| `show-avasthas` | `divisional` | Балади / Джаградади / Диптади / Ладжджитади авастхи |
| `show-yogas` | `divisional` | йоги с описанием и условием (Шаша, Веси, …) |
| `show-sade-sati` | — | периоды Саде-Сати с датами и положением Сатурна |
| `show-vargas` | — | набор варг |
| `first-house` | `sign`, `style`, `divisional`, `chart_big`, `type` | карта, развёрнутая от выбранного знака |
| `get-aspects` | `sign`, `style`, `divisional` | компактно: `Sa\|5 8 11` (планеты \| знаки) |
| `get-argala` | `type` (последняя цифра класса: `1`…), `sign`, `style`, `divisional` | знаки аргалы: `2 12 4 10 11 3` |
| `get-timezone` | `id`, `date`, `time` | таймзона по локации |
| `show-localities` | `keyword` | поиск населённых пунктов (координаты) |

Платное / за авторизацией: `show-transits` → `403 Access Denied`. Тем же образом
закрыты вкладки Совместимость, Варшапхала, Мухурта, Транзиты
(`show-compatibility-data`, `show-varshaphala-data`, `show-muhurta*`, `show-transits*`).
Полный список действий в `assets/js/script.js` — около 80, остальные пишущие
(charts/notes/settings) и требуют аккаунта.

## 5. Интерпретации (текстовые описания)

```
POST /windows/analyse_interpretation.php
option_name=lord-in&option_value=5-4&token_security=<токен>
```

Возвращает `#header` + `#content` с текстом. Ключи берутся из `href` у `a.desc`:
`planet?Su`, `in-sign?Su-Cn`, `in-house?Su-4`, `nakshatra?Asl`, `lord-in?5-4`.
Пример (`lord-in?5-4`): «Управитель 5-го Дома в 4-ом — Счастье, много комфорта и
роскоши в жизни, богатство, сильный интеллект…». Ур/Нептун/Плутон описаний не имеют.

**Текстовые интерпретации есть только на `.ru`.** На `.com` тот же запрос отдаёт
«Sorry, no information in English yet» (634 Б). То есть за описаниями — на `.ru`,
за английскими таблицами — на `.com`.

Справочник терминов: `POST /windows/analyse_handbook.php` с `name=functional_beneficence`
(ключи — в `a.handbook[href]`).

## 6. `horoscope.php` — компактная альтернатива

Открыт на обоих доменах без челленджа, ~42 КБ. Содержит: карту, таблицу
«Дом / Знак / Планеты / Управитель в», текстовую сводку по планетам, текущий период
и блок «Важная информация» (Лагна, Лагнеш, лунный знак, накшатра Луны, лунный день,
Атма Карака, сильные и слабые планеты). Хороший источник, если нужен только срез
основных показателей.

## 7. Рекомендации для набора тулов

1. Сессия: `GET https://vedic-horo.com/` → `PHPSESSID` + `token_security`; держать пару вместе.
   Язык выбирается доменом: `.com` — английский, `.ru` — русский.
2. Данные брать через `actions.php` по отдельным действиям, а не парсить `analyse.php`:
   мельче ответы, нет Cloudflare, параметризуется варга/даша/уровень.
   Если нужны и английские подписи, и тексты интерпретаций — придётся держать две
   сессии, по одной на домен.
3. Парсинг по классам/атрибутам (`.house`, `span.planet.<Xx>`, `tr[start]`, `a.desc[href]`),
   не по позиции и не по локализованному тексту.
4. Токен истекает вместе с сессией; на `419` от сайта — перечитать главную и повторить.
5. Ответы кэшировать: расчёты на стороне сайта не бесплатные (заявлено 35 000 карт/день).

## 8. Воспроизведение

`scripts/probe.sh` поднимает сессию и складывает ответы всех перечисленных действий
в указанный каталог:

```sh
scripts/probe.sh                      # .com (английский) → ./probe-out
scripts/probe.sh https://vedic-horo.ru ./out-ru
```

## 9. Уточнения, найденные при реализации тулов

* **`.ru` отдаёт JS-заглушку.** Периодически (похоже, по числу запросов с IP)
  любой путь на `vedic-horo.ru` начинает возвращать страницу на 13.6 КБ, которая
  из JavaScript ставит cookie `__jua_` с User-Agent'ом и перезагружается. Токена
  на ней нет, так что сессию на `.ru` поднять не получается — включая
  `analyse.php`, который до этого работал. Гейт не обходим (и обходить не будем);
  `Session` распознаёт его и кидает `BootstrapBlocked`. Варианты: работать через
  `.com` или передать `PHPSESSID` + `token_security`, взятые из браузера
  (`Session.adopt`).
* **Главная `.com` — надёжная точка бутстрапа**, токен есть всегда. На `.ru`
  главная его не содержит даже когда гейт не активен: токен печатают только
  страницы приложения (`analyse.php`, `horoscope.php`).
* **Число колонок в таблице планет зависит от варги.** У D1 их 15, у остальных
  14: колонка «Накшатра» есть только в D1. Позиции колонок после неё съезжают,
  поэтому парсер определяет раскладку по ширине строки.
* **`<select>` в ответе не отражает запрошенную варгу** — сервер отдаёт значение
  по умолчанию для сессии, а нужную опцию сайт выбирает уже в JS. Судить о варге
  по ответу можно только по наличию колонки «Накшатра»; `api.show_info()`
  записывает в результат то, что было запрошено.
* **САВ — сумма семи планетных БАВ**, БАВ асцендента показывается рядом, но в
  сумму не входит (проверено на всех 12 домах).
* **`show-info` для варги ≠ D1 не отдаёт знак этой варги.** Пересчитываются
  `Градусы`, `Дом`, бинду и балы, а колонка «Раши» продолжает показывать
  натальный D1-знак, «Навамша» — D9-знак. Знак в самой варге есть только в
  `show-chart` (для D9 он совпадает с колонкой «Навамша»). Проверено на всех
  десяти телах.
* **У `show-chart` две несовместимые разметки.** `style=North` → `div.chart-north`
  с 12 `div.house` в порядке домов, каждый называет свой знак (`.sign a[href=sign?Ar]`,
  `title` — полное имя), аспекты в `<u>`. `style=South` → `table.chart` с 12
  `td.houses` в порядке знаков, каждая называет свой дом (`.house a[href=house?12]`),
  аспекты — просто текст. Градусы в рисунке целые, ретроградность — непустой
  `div.retrograde` с `R`. Оба стиля несут `div.chart-data` с эхом введённых данных.
* **`show-other` — единственный ответ без разметки.** Пять таблиц подряд, в
  ячейках только текст: ни классов, ни `href`, ни `title`. Опознавать строки и
  колонки можно лишь по позиции. Порядок: особые лагны (15 строк), панчанга
  (7 колонок), упаграхи (`#upagrahas`, 11 строк), отдельные точки (8 колонок:
  айянамша … виша навамша), чакры (6 строк). Номер и название чакры лежат в
  одной ячейке через ` | `. Многострочные ячейки (`<br>`) — это «от Асцендента»
  и «от Луны».
* **В `show-other` знак следует за варгой** (в отличие от `show-info`): для D9
  Бхава Лагна переезжает из 08°43\'54\'\' Овна в 18°35\'06\'\' Близнецов — ровно
  навамша от натальной. Панчанга и айянамша от варги не зависят.
* **`show-dasha` — самый удобный для парсинга ответ.** Границы периодов лежат в
  атрибутах строки (`<tr start="23.11.1978 16:25" end="23.11.1997 13:21">`),
  управители — в классах `<span class="Sa">`, так что текст можно игнорировать
  полностью. Колонки: цепочка, дата начала, время (`.hide`), возраст, пустая
  (`.hide`).
* **Знаковые даши кодов не дают.** `chara_rao` и `narayana` печатают знаки
  обычным текстом («Aries-Taurus»), без `<span>`, поэтому доступны только
  локализованные названия. Сопоставление имя→код можно взять из `show-chart`
  того же языка.
* **Границы даш непрерывны только до минуты.** Время приходит как `HH:MM`, и на
  стыках маха-даш стороны иногда округляются по-разному (последняя антара
  Сатурна кончается 13:20, маха Меркурия начинается 13:21). На строгую
  непрерывность полагаться нельзя.
* Уровни: 1 маха, 2 антар, 3 пратьянтар, 4 сукшма. Объём растёт быстро:
  вимшоттари level 1 — 9 строк (1.7 КБ), level 2 — 81 (17 КБ), level 3 — 729
  (175 КБ).
* **`show-bala` — четыре таблицы с группированными шапками.** Шад-бала
  (7 планет), варга-балы (9 — с узлами), матрица аспектов на планеты (7×9) и на
  дома (7×12, класс `aspects-info`). Колонки объявлены через `colspan`, а ячейки
  перекрывают группы неравномерно: у Шад/Стхана/Диг/Кала/Чешта это пара
  «процент + вирупы» (у Шад-балы ещё рупы = вирупы/60), у Дрик/Наисаргика/
  Йуддха/Ишта/Кашта — одно число. Дрик-бала бывает отрицательной.
  `show-shad-bala` — та же первая таблица отдельно, втрое меньше.
* **Наборы варг опознаются по числу в подписи** («Shodasha Varga (16)»), а не по
  словам — это работает на обоих языках.
* **В матрицах аспектов две нижние строки — суммы**: `+` складывает аспекты
  благодетелей, `−` вредителей, ячейки с символами `+`/`-` дают ноль (проверено
  по всем колонкам). Кто благодетель — вердикт этой карты, он лежит в классе
  подписи строки (`green`/`red`) и совпадает с колонкой «ЕБ» в `show-info`.
* **Проценты Шад-балы совпадают** с колонкой «Шад-бала» в `show-info` — это две
  проекции одного расчёта.
* **`show-yogas` отдаёт только образовавшиеся йоги** — голым набором `<tr>` без
  таблицы. Колонки: название, планеты, эффект, условие. Категория лежит в
  атрибуте `type` первой ячейки и **переводится** («Махапуруша»), поэтому нужна
  таблица соответствий. На четырёх разных картах встретились ровно шесть
  категорий: Mahapurusha, Solar, Lunar, Nabhasa, Raja + Dhana, Other. Токен
  `All` в колонке планет остаётся английским и в русском ответе.
* **`show-avasthas` — три таблицы и легенда.** Балади и джаградади приходят с
  силой в `<u>[50% strength]</u>`; диптади и ладжджитади — двумя параллельными
  колонками «состояние / причина», где коды планет и знаков остаются латиницей;
  шаянади — с пятью колонками групп слогов (сила зависит от первого слога
  имени), группы тоже латиницей на обоих языках. Легенда `#shayanadi-info`
  перечисляет только встретившиеся состояния, число в скобках — сколько планет
  в этом состоянии. Цвет (`green`/`orange`/`red`) строго следует за силой
  100/50/ниже. В шапке таблицы шаянади есть `colspan=2`, без разворота колонок
  группы слогов съезжают на одну.
